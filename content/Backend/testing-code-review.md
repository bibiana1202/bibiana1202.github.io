> “현재 회사에서는 일정과 팀 규모 때문에 자동화된 테스트 코드를 충분히 구축하지 못했습니다. 이 부분은 제 경험에서 부족하다고 생각하고 있고, 변경 시 regression을 줄이고 안정적인 배포를 하기 위해 필요한 부분이라고 생각합니다.”


### Question?
□ Unit Test  
□ Integration Test  
□ 왜 테스트를 작성하는가  
□ 테스트하기 좋은 코드란?  
□ Code Review 목적


---

### Unit Test
- 작은 단위의 로직 하나를 독립적으로 검증하는 테스트
- 외부 DB나 네트워크에 최대한 의존하지 않고, 작은 로직 단위를 빠르게 검증한다.


### Integration Test
- 여러 컴포넌트가 실제로 잘 연결되는지 보는 테스트
- 여러 구성 요소 연결


### 테스트 이유
- 변경 시 기존 기능이 깨졌는지 빨리 확인
- regression 방지
	- regression: 기존에 잘 되는 기능이 새로운 변경 때문에 깨지는것
- 리펙토링 안전성 확보
- 배포 전 신뢰도 향상
- 요구사항을 코드로 명시하는 효과
> 테스트 코드는 변경으로 인해 기존 기능이 깨지는 regression을 줄이고, 리팩토링이나 배포 시 안정성을 높이기 위해 필요하다고 생각합니다.


### 테스트하기 좋은 코드
- 의존성이 분리되어 있고, 함수/모듈의 책임이 명확한 코드


### Mock
- 실제 DB나 외부 API 대신 가짜 객체/동작을 넣는것
- 테스트가 외부 시스템 상태에 영향받지 않게
- 빠르게 실행
- 실패 상황도 쉽게 재현


### 마무리
- 테스트 코드 경험 적을 때 답변
> **“현재 회사에서는 팀 규모와 일정 때문에 자동화된 테스트 코드를 충분히 구축하지 못했습니다. 그래서 이 부분은 제 경험에서 부족한 점이라고 생각합니다. 다만 변경 시 regression을 줄이고 안정적인 배포를 하기 위해 Unit Test와 Integration Test가 중요하다고 보고 있고, 앞으로는 비즈니스 로직과 외부 의존성을 분리해서 테스트 가능한 구조로 작성하는 습관을 더 가져가려고 합니다.”**

- 코드리뷰 경험 적으면?
> **“현재 팀에서는 정형화된 PR 기반 코드리뷰 프로세스가 충분히 자리잡혀 있지는 않았습니다. 대신 변경사항을 팀원과 공유하거나 필요한 부분을 확인하는 정도의 협업은 해왔습니다. 코드리뷰가 단순히 오류를 찾는 과정뿐 아니라 설계 의도를 공유하고 팀의 코드 품질을 맞추는 과정이라고 생각합니다.”**


> **“Unit Test는 작은 로직 단위를 독립적으로 검증하는 테스트이고, Integration Test는 API, DB 등 여러 컴포넌트가 연결된 흐름을 검증하는 테스트입니다. 테스트 코드는 변경에 따른 regression을 줄이고 리팩토링과 배포 안정성을 높이는 데 중요합니다. 테스트하기 좋은 코드는 책임과 의존성이 분리된 코드라고 생각합니다. 코드리뷰는 버그 탐지뿐 아니라 설계 검토와 지식 공유, 코드 품질을 맞추기 위한 과정이라고 생각합니다.”**
