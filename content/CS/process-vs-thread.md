### Process
- 실행 중인 프로그램
- 프로세스 하나가 만들어지면 OS가 그 프로세스가 사용할 자기만의 메모리 공간을 준다.
```
[프로세스 A]       [프로세스 B]

자기 메모리         자기 메모리
   ↓                  ↓
Heap A              Heap B
Stack A             Stack B
```


### Thread
- 프로세스 안에서 실제로 코드를 실행해 나가는 실행 흐름
```
        Process
┌───────────────────────┐
│                       │
│   공유 메모리(Heap)      │
│                       │
│ Thread 1   Thread 2   │
│    ↓          ↓       │
│  Stack 1    Stack 2   │
│                       │
└───────────────────────┘
```
- 같은 프로세스 안의 Thread들은 상당 부분의 메모리를 공유한다. 대표적으로 Heap를 공유.
- 하지만 각 Tread는 자기 Stack를 따로 가지고 있다.

> 프로세스끼리는 기본적으로 메모리가 독립되어 있고, 같은 프로세스 안의 스레드들은 메모리 일부를 공유한다.


### Race Condition
- 두개 이상의 실행 흐름이 공유된 데이터에 동시에 접근하고 변경하면서 실행 순서에 따라 결과가 달라지는 상황
> 여러 스레드가 동시에 같은 데이터를 수정하면 어떻게 되나요?
> : 같은 프로세스의 여러 스레드는 공유 메모리에 접근할 수 있기 때문에 동시에 같은 데이터를 수정하면 race condition이 발생할 수 있습니다. 이를 제어하기 위해 mutex나 lock 등의 동기화 기법을 사용할수 있습니다.


### Mutex/Lock
- Mutex(Mutual Exclusion) : 한 번에 하나만 들어오게 한다.


### 마무리
> 프로세스와 스레드의 차이는 무엇인가요?
> : 프로세스는 실행 중인 프로그램으로 각각 독립적인 메모리 공간을 가지고 있습니다. 스레드는 프로세스 내부에서 코드를 실행하는 실행 흐름이고, 같은 프로세스의 스레드들은 Heap 같은 메모리 영역을 공유하지만 각각 별도의 Stack을 가집니다.

> 여러 스레드가 같은 데이터를 동시에 수정하면요?
> : 공유 데이터에 동시에 접근해서 수정하면 실행 순서에 따라 결과가 달라지는 Race Condition이 발생할 수 있습니다. 이를 방지하기 위해 Mutex나 Lock 같은 동기화 기법을 사용할 수 있습니다.
